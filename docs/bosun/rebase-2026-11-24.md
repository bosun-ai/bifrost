## Method and scope

Reviewed every fork-only commit reachable from the fetched origin branches:
14 on `bosun` (including its merge), the pending streaming PR, and 13 additional
commits on historical branches. Compared behavior and upstream tests, not only
patch IDs: upstream often fixed the same bug with different code. Also inspected
merge conflict resolutions, which only reconcile historical changelog entries
and harness folders. All retained production regressions were reproduced with
failing Go tests before applying their fixes.

## Request-path costs

Median of three `-benchmem` runs on an Apple M1 Max, Go 1.27.4. Columns are
**upstream / rebased**. These local microbenchmarks are not production latency
measurements; timing and byte counts vary with background load and pooling.

| Benchmark | ns/op | B/op | allocs/op |
| --- | ---: | ---: | ---: |
| `ToolSchemaMarshal` | 13371 / 14812 | 8537 / 8503 | 80 / 80 |
| `ToOpenAIChatRequestMistral` | 4645 / 5585 | 7432 / 7432 | 73 / 73 |
| `OpenAIChatRequestMarshal` | 16891 / 17692 | 8068 / 7961 | 49 / 49 |
| `InvokeIngress_ToolResult/string_content` | 27503 / 27685 | 41714 / 42170 | 396 / 393 |
| `InvokeIngress_ToolResult/tool_reference` | 29621 / 29410 | 44285 / 43808 | 425 / 422 |
| `MistralContentNormalization/thinking` | 2848 / 2974 | 1867 / 1876 | 28 / 28 |
| `MistralContentNormalization/string` | 265.9 / 329 | 32 / 32 | 1 / 1 |
| `MistralRequestMarshaling/plain` | 1651 / 1641 | 321 / 324 | 7 / 7 |
| `MistralRequestMarshaling/reasoning` | 1695 / 6293 | 322 / 4539 | 7 / 44 |

Plain Mistral serialization adds no allocations. Native reasoning replay now
preserves data that upstream discarded: the single-message fixture adds about
4.6 microseconds and 37 allocations. Processing is limited to assistant messages
with reasoning; other providers skip this encoding. Sharing upstream's content
normalizer with unary responses adds a first-choice shape check (about 63 ns in
the string-delta fixture), with no additional allocations. Bedrock Invoke avoids
three allocations by no longer recursively creating a nested cache-point slice.
Prompt-cache schema validation runs at configuration load, not per request.

No new global cache, per-credential state, goroutine, or retained stream state is
introduced. Rewriting uses temporary buffers proportional to the current request
or response payload; they become collectible with that operation. There is no
additional storage that grows across requests.

## Live verification before rollout

Per the repository's agent instructions, the operator runs the paid provider
harness. Port 8187 was checked free locally while preparing this change. From
the repository root, start the backing service and gateway:

```sh
docker compose -f tests/docker-compose.yml up -d weaviate
make dev PORT=8187 APP_DIR="$(pwd)/tests/integrations/python"
```

In another terminal in the same checkout, with the provider credentials configured:

```sh
make run-provider-harness-test FEATURE="bosun-rebase" BASE_URL=http://localhost:8187
make run-provider-harness-test SMOKE=1 BASE_URL=http://localhost:8187
```

Weaviate uses HTTP port 9000 and gRPC port 50051. The focused run includes an
intentionally padded Bedrock tool result to exceed its cache minimum. Every
unexpected HTTP status in the retained cases is a failure. After reviewing and
adopting the PR, use the existing manual **Publish Bosun ECR image** workflow on
`bosun`, then update the deployment to the published immutable SHA tag.
